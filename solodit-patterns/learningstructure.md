Per finding, ~30 min:

1. Read the finding (~10 min)
   On the Solodit page, read in this order:

Title + severity
Description / Summary (the auditor's, not AI)
Impact
Code snippets
PoC if included
Then Recommendation (last — don't spoil the fix)

Skip: AI summary, comments.

2. Close the tab. Explain it in your own words (~5 min)

What does the protocol do?
What's the bug?
Why is it bad?

Can't answer one? Re-open, re-read just that part, close, try again.

3. Ask: "why did the dev write it this way?" (~5 min)
   Not what they forgot. What were they thinking that made it seem fine?

Write one sentence.

4. Save it in a pattern file (~5 min)

Fits existing pattern → add to ## Instances seen
New pattern → new file, your template + the "Why devs get this wrong" line from step 3

5. Write one flinch trigger (~5 min)
   "Next time I see \_\_\_ in code, I should be suspicious."

One line.
